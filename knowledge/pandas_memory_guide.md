
# Pandas 데이터 처리 한계 및 대용량 데이터 처리 가이드

## 1. Pandas의 최대 데이터 처리 건수
Pandas 자체에는 하드코딩된 **최대 행(Row) 수나 데이터 건수의 제한은 없습니다**. 처리 가능한 최대 데이터 크기는 전적으로 **시스템의 가용 메모리(RAM) 크기**에 비례합니다.

## 2. 메모리(RAM) 요구량의 법칙 (Rule of Thumb)
데이터 사이언스 실무에서는 일반적으로 Pandas가 데이터를 원활하게 처리하기 위해 **원본 데이터 크기의 5배 ~ 10배에 달하는 RAM**이 필요하다고 봅니다.
* **이유**: Pandas는 데이터를 메모리에 한 번에 통째로 적재(In-memory)하여 연산하며, 데이터 병합(`merge`), 그룹화(`groupby`), 결측치 처리 등 데이터를 변환하는 과정에서 원본 외에 임시 중간 객체(Intermediate object)를 다수 생성하기 때문입니다.
* **예시**: 16GB RAM을 가진 일반적인 로컬 노트북 환경이라면, 약 1.5GB ~ 2GB 크기의 데이터(컬럼 수에 따라 다르지만 보통 수백만 ~ 1천만 건 내외의 행)를 다루는 것이 안전한 한계선입니다.

## 3. 대용량 데이터 한계 극복을 위한 데이터 사이언티스트의 접근법

가용 RAM을 초과하여 `MemoryError`가 발생할 때, 실무에서는 다음과 같은 기법들을 활용합니다.

### A. Pandas 내부 최적화 기법
1. **데이터 타입 다운캐스팅 (Downcasting)**
   * `float64`나 `int64`로 기본 할당된 숫자형 데이터를 값의 범위에 맞게 `float32`, `int16` 등으로 낮춰 메모리 사용량을 크게 줄입니다.
2. **범주형(Category) 데이터 변환**
   * 고유값이 적고 반복되는 문자열(String/Object) 데이터를 `category` 타입으로 변환하여 메모리를 극적으로 절약합니다.
3. **청크(Chunk) 단위 분할 처리**
   * `pd.read_csv('file.csv', chunksize=100000)`를 사용하여 전체 데이터를 한 번에 읽지 않고, 10만 건씩 잘라서 읽은 뒤 집계 연산(Aggregation) 결과만 누적하는 방식을 사용합니다.

### B. 효율적인 데이터 포맷 활용
* 앞서 문의하셨던 **Parquet(파케이)**나 **Feather** 포맷은 CSV보다 압축률이 우수하고 데이터 타입을 보존합니다. 특히 파케이는 컬럼 지향(Columnar) 포맷이므로, Pandas 엔진에서 `columns=['주문수', '매출']`처럼 분석에 필요한 특정 컬럼만 지정해 읽어올 때 메모리 효율을 극대화할 수 있습니다.

### C. 대안 라이브러리 및 빅데이터 도구 도입
데이터가 수 GB ~ 수십 GB 이상으로 넘어가면 Pandas를 고집하기보다 다음 도구들을 활용합니다.
* **Polars (폴라즈)**: Rust 기반의 차세대 데이터프레임 라이브러리로, 멀티스레딩과 지연 평가(Lazy Evaluation)를 통해 Pandas보다 월등히 빠르고 메모리 최적화가 잘 되어 있습니다.
* **Dask (다스크)**: Pandas와 문법이 90% 이상 동일하지만, 데이터를 작게 쪼개어 디스크와 메모리를 교환해가며 처리(Out-of-core)하기 때문에 RAM 용량을 초과하는 데이터도 무리 없이 연산합니다.
* **Spark / SQL 데이터 웨어하우스**: 수백 GB 이상 수 테라바이트급 데이터라면, 로컬이 아닌 PySpark 클러스터를 이용하거나 구글 BigQuery(SQL) 측에 연산을 위임한 후, 1차 집계가 완료된 작은 요약 데이터만 Pandas로 가져와 시각화 및 머신러닝(RandomForest, GradientBoosting 등) 모델링을 수행합니다.
